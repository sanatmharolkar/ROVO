Abstract

The upper alignment module of the Remote Operation of Vehicles Ontology (R.O.V.O) holds every axiom that links R.O.V.O to other ontologies: the EDMC AUTO Vehicle Automation Levels ontology (SAE J3016) and the Automotive Urban Traffic Ontology (A.U.T.O.). Keeping these links in one module lets each reused source be replaced without changing the other modules.

Introduction back to ToC

R.O.V.O, the Remote Operation of Vehicles Ontology, describes the context of remote driving (road vehicle teleoperation). It has three modules: the [operator awareness module](https://sanatmharolkar.github.io/ROVO/docs/op/) (`ROVO-op`), the [communication link module](https://sanatmharolkar.github.io/ROVO/docs/link/) (`ROVO-link`) and the [upper alignment module](https://sanatmharolkar.github.io/ROVO/docs/core/) (`ROVO-core`). SHACL shapes for incoming data and the Turtle files are in the [repository](https://github.com/sanatmharolkar/ROVO). This module imports the operator awareness module and adds the links to other ontologies: - **Subclass axioms** only where every instance of the subclass is clearly an instance of the superclass, e.g. an EDMC remote driver is a remote operator, and an A.U.T.O. traffic entity is a situation element. - **SKOS mapping properties** (`skos:closeMatch`, `skos:broadMatch`, `skos:narrowMatch`, `skos:relatedMatch`) where one concept is wider than the other or the two only overlap. They add no class-level entailments. - **Tasks of the remote driving mode**, which are EDMC classes: lateral and longitudinal vehicle motion control, object and event detection and response, and the DDT fallback. The reused classes are declared with their original IRIs and `rdfs:isDefinedBy` their source, so that R.O.V.O can be used without loading the full sources.
